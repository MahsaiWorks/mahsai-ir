# جریان سادهٔ تولید و انتشار محتوا

این مخزن از Astro Content Collections به‌عنوان مدیریت محتوای فایل‌محور استفاده می‌کند؛ یعنی هر مقاله یک فایل Markdown قابل نسخه‌بندی است و برای انتشار به پنل یا پایگاه داده نیاز ندارد.

## ساخت پیش‌نویس

```bash
pnpm content:new -- --slug=english-kebab-slug --title="عنوان فارسی" --description="پاسخ روشن صفحه" --cluster=files
```

خوشه یکی از `files`، `clients`، `marketing` یا `legal` است. فرمان، فایل تازه را با `draft: true` می‌سازد و فایل موجود را بازنویسی نمی‌کند.

## مسیر هر مطلب

1. انتخاب سؤال از نقشهٔ کلیدواژه و تقویم تحریریه؛
2. ثبت منبع، نمونهٔ واقعیِ بی‌نام یا مصاحبهٔ دارای رضایت؛
3. ساخت پیش‌نویس و نوشتن جواب کوتاه قبل از جزئیات؛
4. افزودن تصویر مرتبط، متن جایگزین و منبع تصویر؛
5. اجرای کامل `docs/CONTENT_QUALITY_CHECKLIST.md`؛
6. بازبینی حقوقی بیرونی برای ادعای حساس؛
7. تغییر `draft` به `false` فقط پس از کنترل؛
8. اجرای `pnpm quality` و انتشار؛
9. بررسی صفحهٔ زنده و افزودن URL به Search Console در صورت نیاز؛
10. بازبینی پس از ۹۰ روز یا زودتر اگر منبع/محصول تغییر کرد.

## اصلاح مطلب منتشرشده

- خطای واقعی فوراً اصلاح و تاریخ `updatedAt` تغییر داده می‌شود.
- فقط تغییر تاریخ بدون اصلاح معنادار ممنوع است.
- اصلاح مهم در سیاست تحریریه یا یادداشت خود مقاله توضیح داده می‌شود.
- حذف URL فقط با redirect به نزدیک‌ترین پاسخ مفید انجام می‌شود.

## گزارش تازگی

`pnpm audit:stale` مقاله‌های بیش از ۹۰ روز و تاریخ بررسی بازار را گزارش می‌کند. این گزارش به‌تنهایی دستور حذف یا تازه‌کردن مصنوعی تاریخ نیست.
