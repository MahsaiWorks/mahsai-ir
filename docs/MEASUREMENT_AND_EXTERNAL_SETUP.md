# سنجش رشد و اتصال‌های بیرونی

این سند مرز میان کد آماده‌شده و کارهایی را روشن می‌کند که فقط مالک حساب می‌تواند انجام دهد. هیچ توکن، رمز، کد یک‌بارمصرف یا اطلاعات هویتی نباید در گفت‌وگو یا مخزن ثبت شود.

## وضعیت اتصال‌ها

| بخش                      | وضعیت کد                                                                    | اقدام مالک                                                                                      |
| ------------------------ | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| sitemap و robots.txt     | فعال؛ sitemap در Search Console با وضعیت Success و ۵۵ صفحهٔ کشف‌شده ثبت است | پس از هر انتشار پوشش صفحه‌های تازه کنترل شود                                                    |
| Google Search Console    | Property دامنه تأیید است؛ خط مبنای جست‌وجو و ایندکس ثبت شد                  | گزارش Performance و Indexing هفته‌ای یک‌بار بازبینی شود                                         |
| Bing Webmaster Tools     | نیازمند حساب                                                                | ورود و افزودن دامنه؛ در صورت امکان پس از تأیید Google از Import استفاده شود                     |
| IndexNow                 | کلید، فایل عمومی و اسکریپت ارسال آماده است                                  | ندارد؛ بعد از هر انتشار با `pnpm indexnow:submit` اجرا می‌شود                                   |
| Cloudflare Web Analytics | فعال؛ مشاهدهٔ ۳۰ مرداد در بازهٔ ۳۰روزه هنوز دادهٔ کافی نشان نمی‌دهد         | پس از رسیدن به نمونهٔ کافی، Core Web Vitals و مسیرهای پرتکرار بررسی شود؛ token در کد قرار نگیرد |
| رویدادهای رفتاری         | Worker و D1 مستقل فعال‌اند و `mahsai:measure` با `sendBeacon` متصل شده است  | خلاصهٔ روزانه هفته‌ای یک‌بار از View خصوصی D1 خوانده شود                                        |
| انتساب نصب متراژ         | endpoint مستقل، idempotent، محدودشده و متصل به نسخهٔ بازار فعال است         | پس از انتشار نسخهٔ تازه، نصب واقعی با همان `event_id` روی گوشی آزموده شود                       |
| خطاهای مرورگر            | رویداد بدون متن خطا منتشر می‌شود                                            | اتصال به سرویس خطا فقط پس از انتخاب سرویس و بازبینی حریم خصوصی                                  |

## قرارداد رویدادها

رویدادها اطلاعات فرم، نام مشتری، شماره تماس، مقصد کامل یا متن خطا را ثبت نمی‌کنند. payload ذخیره‌شده فقط نام رویداد از فهرست مجاز، مسیر بدون Query String، جایگاه ثابت و ساعت تهران است. IP خام و User-Agent در D1 ذخیره نمی‌شوند.

جمع‌کنندهٔ سایت روی `POST /api/events` و سرویس جداگانهٔ نصب روی `POST /api/metrazh/attribution` قرار دارند. route دقیق‌تر انتساب نصب بر route عمومی `/api/*` مقدم است؛ بنابراین کد و پایگاه نصب با سنجش سایت مخلوط نمی‌شوند.

| رویداد                       | معنا                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------ |

| `content_share`              | انتخاب اشتراک‌گذاری مطلب در تلگرام یا واتس‌اپ                                        |

قیف پایه برای گزارش هفتگی:

`ورودی جست‌وجو → راهنمای جامع یا مقاله → صفحهٔ متراژ → کلیک کافه‌بازار`

## آزمایش متن اقدام اصلی

- مبنای فعلی: «دریافت مستقیم از کافه‌بازار»
- گزینهٔ بعدی: «نصب متراژ و شروع اولین فایل»

آزمایش فقط وقتی شروع می‌شود که ابزار سنجش فعال، حجم داده کافی و یک معیار موفقیت مشخص وجود داشته باشد. پیش از آن تغییر تصادفی متن فقط نتیجه را مبهم می‌کند.

## ترتیب اقدام مالک

1. ورود به Bing Webmaster Tools و افزودن دامنه؛ این گام به ورود حساب Microsoft یا Google نیاز دارد.
2. بازبینی هفتگی Search Console و ثبت پرسش‌های تازه فقط پس از نمایش کافی.
3. بازبینی Web Analytics پس از یک هفته و تکمیل Core Web Vitals در صورت وجود دادهٔ کافی.
4. نگه‌داشتن token تحلیل فقط در محیط ساخت؛ نه گفت‌وگو یا commit.
5. خواندن هفتگی Viewهای خصوصی `mahsai_site_event_daily_summary` و `metrazh_install_attribution_daily_summary` فقط پس از ورود مالک به Cloudflare.
