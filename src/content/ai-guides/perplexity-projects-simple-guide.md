اگر یک تحقیق چند روز طول می‌کشد، گفت‌وگوهای پراکنده خیلی زود گم می‌شوند. Project در Perplexity برای همین موقعیت ساخته شده است: فایل‌ها، گفت‌وگوها و دستورهای ثابت یک کار را در یک فضای مشترک نگه می‌دارد.

## فرق فضای پروژه با یک گفت‌وگوی معمولی چیست؟

یک چت معمولی برای سؤال سریع مناسب است. Project برای کاری است که قرار است به آن برگردید؛ مثل بررسی بازار، آماده‌کردن گزارش یا دنبال‌کردن یک موضوع در چند مرحله.

داخل Project می‌توانید گفتگوها، فایل‌ها و دستورهای ثابت را کنار هم داشته باشید. بعضی قابلیت‌ها و سقف‌ها به نوع حساب وابسته‌اند؛ پس صفحهٔ رسمی حساب خودتان را بررسی کنید.

## چه چیزی داخل فضای پروژه بگذاریم؟

یک Project خوب معمولاً این چهار بخش را دارد:

1. یک نام روشن؛
2. توضیح یک‌جمله‌ای هدف؛
3. چند منبع یا فایل مرتبط؛
4. دستور ثابتی برای شکل پاسخ.

نمونهٔ دستور:

```text
پاسخ‌ها را کوتاه و فارسی بنویس.
هر ادعای زمانی را با لینک منبع همراه کن.
واقعیت، برداشت و پیشنهاد را در سه بخش جدا نشان بده.
اگر منبع کافی نیست، حدس نزن.
```

## چه چیزی را وارد نکنیم؟

Project فضای ابری است. قبل از افزودن هر فایل، ببینید آیا اجازهٔ بارگذاری آن را دارید. اطلاعات هویتی، رمز، پروندهٔ پزشکی، قرارداد محرمانه یا دادهٔ مشتری را فقط به‌خاطر راحتی وارد نکنید.

نوع حساب سازمانی و تنظیمات داده می‌تواند با حساب شخصی فرق داشته باشد. برای کار حساس، سیاست رسمی همان حساب معیار است.

## یک آزمایش ده‌دقیقه‌ای

برای شروع، یک پروژهٔ کوچک بسازید:

- موضوع: مقایسهٔ سه منبع عمومی؛
- فایل: فقط منابع غیرمحرمانه؛
- خروجی: جدول ادعا، منبع و تاریخ؛
- معیار قبولی: هیچ عددی بدون لینک پذیرفته نشود.

بعد از یک دور کار، از خودتان بپرسید: آیا Project واقعاً پیدا کردن اطلاعات و ادامهٔ کار را آسان‌تر کرد؟ اگر پاسخ منفی است، شاید برای آن کار یک گفت‌وگوی معمولی کافی باشد.

## جمع‌بندی

Project زمانی ارزش دارد که کار شما ادامه‌دار، منبع‌محور و چندمرحله‌ای باشد. برای سؤال‌های کوتاه، ساختن Project فقط یک لایهٔ اضافه است. ابزار را به اندازهٔ مسئله انتخاب کنید.
