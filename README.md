# وب‌سایت mahsai.ir

نسخه نخست وب‌سایت شخصی، نمونه‌کارها و مرکز رسمی پشتیبانی اپلیکیشن‌ها. این پروژه با
Astro، TypeScript سخت‌گیرانه و خروجی کاملاً ایستا ساخته شده و برای انتشار روی GitHub
Pages با دامنه اصلی `https://mahsai.ir` آماده است.

## فناوری و معماری

- Astro 7 و تولید کاملاً ایستا
- TypeScript با تنظیم `strictest`
- مجموعه‌های محتوای تایپ‌شده برای اپلیکیشن‌ها و مقالات
- CSS مستقل، واکنش‌گرا، راست‌به‌چپ و بدون کتابخانه رابط کاربری
- پشتیبانی خودکار از رنگ‌بندی روشن و تیره
- متادیتای SEO، نشانی canonical، Open Graph، robots.txt و sitemap
- بدون بک‌اند، پایگاه‌داده، ورود کاربر، CMS یا کلید محرمانه

## پیش‌نیازها

- Node.js نسخه `24`؛ حداقل نسخه سازگار `22.12.0`
- pnpm نسخه `11`

## اجرای محلی

```bash
pnpm install
pnpm dev
```

نشانی نمایش‌داده‌شده در ترمینال را در مرورگر باز کنید. برای دیدن نسخه تولیدی:

```bash
pnpm build
pnpm preview
```

## ویرایش محتوا

همه اطلاعات قابل ویرایش از اجزای رابط جدا شده‌اند:

- `src/config/site.ts`: نام برند، نام توسعه‌دهنده، عنوان، زندگی‌نامه، ایمیل پشتیبانی،
  شبکه‌های اجتماعی، پیوندهای فروشگاه و تنظیمات پیش‌فرض SEO.
- `src/content/apps/*.json`: هر اپلیکیشن شامل نام، توضیح کوتاه و کامل، آیکون،
  اسکرین‌شات‌ها، پلتفرم‌ها، وضعیت، پیوند فروشگاه، پشتیبانی و حریم خصوصی است.
- `src/content/articles/*.md`: مقاله‌های آموزشی، توضیحات SEO، تاریخ، دسته‌بندی و زمان
  مطالعه.
- `src/data/projects.ts`: پروژه‌های منتخب.
- `src/data/specialties.ts`: تخصص‌ها و متن معرفی آن‌ها.
- `src/pages/privacy.astro` و `src/pages/terms.astro`: سیاست حریم خصوصی و شرایط استفاده
  متراژ بر اساس وضعیت فعلی محصول؛ پیش از انتشار عمومی بازبینی حقوقی توصیه می‌شود.

برای افزودن اپلیکیشن، فایل JSON موجود در `src/content/apps/` را الگو قرار دهید،
نام فایل یکتا انتخاب کنید و همه مقدارهای جایگزین را تغییر دهید. وضعیت باید یکی از این
مقادیر باشد: `development`، `beta`، `available` یا `archived`.

برای آیکون و اسکرین‌شات واقعی، فایل‌ها را در `public/images/apps/<app-name>/` قرار دهید
و مسیرهایی مانند `/images/apps/<app-name>/icon.png` را در JSON ثبت کنید.

برای افزودن مقاله، یک فایل Markdown در `src/content/articles/` بسازید و فیلدهای frontmatter
را مطابق مقاله موجود تکمیل کنید. مقاله‌ای که `draft: true` داشته باشد در خروجی عمومی نمایش
داده نمی‌شود.

## بررسی کیفیت

```bash
pnpm format:check
pnpm check
pnpm build
```

برای اصلاح خودکار قالب‌بندی:

```bash
pnpm format
```

خروجی نهایی در `dist/` ساخته می‌شود. پیش از انتشار، پوشه خروجی باید شامل صفحات اصلی،
`404.html`، `robots.txt` و فایل‌های sitemap باشد.

## انتشار روی GitHub Pages

فایل `.github/workflows/deploy.yml` از اکشن رسمی Astro استفاده می‌کند. چون سایت روی
دامنه ریشه منتشر می‌شود، در `astro.config.mjs` عمداً هیچ `base` تعریف نشده است.

1. یک مخزن خالی در GitHub بسازید؛ هنگام ساخت آن README یا فایل دیگری اضافه نکنید.
2. در پوشه پروژه دستورهای زیر را اجرا کنید و مقدارهای جایگزین را با نشانی مخزن خود عوض
   کنید:

   ```bash
   git init
   git add .
   git commit -m "Build initial mahsai.ir website"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPOSITORY.git
   git push -u origin main
   ```

3. در GitHub به `Settings → Pages` بروید و در بخش Build and deployment، منبع را روی
   `GitHub Actions` قرار دهید.
4. اجرای workflow با push شاخه `main` شروع می‌شود. نتیجه را در زبانه `Actions` بررسی
   کنید.

## اتصال دامنه اصلی mahsai.ir

1. در تنظیمات حساب GitHub به `Settings → Pages → Add a domain` بروید، `mahsai.ir` را
   اضافه کنید و رکورد TXT پیشنهادی GitHub را در پنل DNS دامنه ثبت کنید. رکورد TXT را پس
   از تأیید حذف نکنید.
2. در `Settings → Pages` همان مخزن، مقدار Custom domain را `mahsai.ir` قرار دهید.
3. در پنل DNS ثبت‌کننده دامنه، رکوردهای A زیر را برای میزبان `@` ثبت کنید و رکوردهای A
   یا AAAA متناقض را حذف کنید:

   ```text
   185.199.108.153
   185.199.109.153
   185.199.110.153
   185.199.111.153
   ```

4. برای `www` یک رکورد CNAME به `USERNAME.github.io` بسازید و `USERNAME` را با نام
   کاربری یا سازمان GitHub خود عوض کنید.
5. پس از تأیید DNS و صدور گواهی، گزینه `Enforce HTTPS` را فعال کنید. انتشار DNS و آماده
   شدن HTTPS ممکن است زمان ببرد.

از رکورد wildcard مانند `*.mahsai.ir` استفاده نکنید. در انتشار مبتنی بر GitHub Actions،
فایل CNAME لازم نیست و دامنه از تنظیمات Pages مدیریت می‌شود.

## افزودن زبان انگلیسی در آینده

محتوا اکنون فارسی و `fa-IR` است. برای افزودن انگلیسی، داده‌های `config`، `content` و
`data` را به پوشه‌های locale منتقل کنید، مسیرهای انگلیسی را زیر `/en/` بسازید و در layout
بر اساس locale مقدارهای `lang`، `dir`، canonical و `hreflang` را تنظیم کنید. اجزای فعلی
برای نگه‌داشتن داده بیرون از UI طراحی شده‌اند تا این مهاجرت ساده بماند.
